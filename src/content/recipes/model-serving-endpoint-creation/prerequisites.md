Verify these Databricks workspace features are enabled before starting. If any check fails, ask your workspace admin to enable the feature.

- **Model Serving enabled.** Run `databricks serving-endpoints list --profile <PROFILE>` and confirm the command succeeds (an empty list is fine — you are about to create an endpoint). A permission or `not enabled` error means Model Serving is not available to this identity.
- **Permission to create serving endpoints.** Creating an endpoint requires workspace membership with the `workspace-access` entitlement; `CAN_MANAGE` is a per-endpoint ACL that governs managing an endpoint after it exists. If `databricks serving-endpoints create` returns `PERMISSION_DENIED`, ask your admin to check your entitlements.
- **A foundation model or registered MLflow model to serve.** List the foundation-model endpoints already available in your workspace with `databricks serving-endpoints list --profile <PROFILE> -o json` (look for names starting with `databricks-`). If you plan to serve a registered Unity Catalog model instead, confirm it exists in the Databricks UI under **Models** before running `databricks serving-endpoints create`.
